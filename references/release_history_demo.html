История релизов

Показываем, что изменилось для сотрудников и какие задачи вошли в версию.

ДЕМОНСТРАЦИЯ: версии вымышлены и не были опубликованы.

После каждой задачи

1. Issue → отдельная ветка
2. PR + unit/integration/E2E
3. Task change note → docs/changes/WB-XX.md
4. Develop regression + Allure
5. Staging → проверка
6. GitHub Release → version/latest → prod smoke

В реальном приложении история строится только из успешно опубликованных версий; если релизов нет, выводится пустое состояние.
