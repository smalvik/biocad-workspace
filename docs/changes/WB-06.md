# WB-06 · AI + MCP

## Пользовательское изменение
Реализуется чат поиска FreeDesk/переговорной, предложение на плане и отдельное
подтверждение точного ресурса/периода. Ветка ещё не выпущена; live LLM-проверка
ожидает согласованной модели и лимита расходов.

## Реальная реализация
- Booking RPC через RabbitMQ переиспользует те же auth/CSRF/booking handlers внутри
  процесса; Assistant не обращается к Booking по HTTP и не читает БД.
- Официальный MCP SDK 2.3.0: отдельный STDIO-процесс, discovery и вызовы реальных
  `search_employees`, `list_spaces`, `get_availability`, `get_space_details`;
  `propose_booking` только читает доступность и подписывает предложение.
- OpenRouter tool calling, ограниченные размер/время/раунды, без резервной модели
  (WB-12). Модель не получает session/CSRF/API keys и не имеет write-tool.
- User-bound предложение на 10 минут, отдельный `/assistant/confirm`, стабильный
  ключ повторов/перезагрузки, прежние PostgreSQL GiST/idempotency/outbox правила.
  Истёкшее предложение может восстановить прежний commit в течение 8 часов,
  но не создать новую бронь.
- Аддитивная миграция `0003_assistant_limits`: конкурентные rate windows и
  консервативный общий лимит расходов, не сбрасываемый рестартом. По умолчанию 0 USD.
- Согласие перед отправкой текста, закрытие ожидающего чата, ручная форма при сбое;
  mobile preview использует карточку AI без перекрывающей её панели места.
- [Контракт и эксплуатация](../architecture/ASSISTANT.md).

## Риски и rollback
Схема аддитивна, существующие брони/пользователи не меняются. Брокер/LLM не входят
в readiness Booking и не нужны ручной форме. Предыдущие runtime digests остаются
средством rollback; новые таблицы лимитов не удалять при откате образов.

## Уточнение: только бесплатная модель

Пользователь выбрал «Только бесплатная модель», [решение](../requirements/DECISIONS.md).

`max_price={prompt:0,completion:0,request:0}` на каждом запросе, без paid fallback.

и отвергает платную ветку. Повтор 429 ограничен одной попыткой с Retry-After.
