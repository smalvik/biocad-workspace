# WB-05 · Форма бронирования

## Пользовательское изменение
Было: карта и карточка только читали доступность. Реализованы «Продолжить» для
свободных FreeDesk/переговорных, подтверждение точного места/офиса/этажа/периода
МСК, результат с кодом брони, «Мои бронирования» и подтверждённая отмена своей брони.

## Реальная реализация
React/API client: CSRF, стабильный Idempotency-Key и неизменяемый payload,
in-flight guard, проверка соответствия ответа, 409/422/401/network states.
Неизвестный результат сохраняется в sessionStorage с областью текущего employee_id;
после reload/повторного входа доступен явный повтор исходной операции, без переноса
на другой ресурс/время. При недоступном storage повтор в рамках вкладки остаётся
в памяти. Отмена идемпотентна по booking_id. Native modal dialogs обеспечивают
фокус, Escape и inert background; busy действие нельзя закрыть/повторить.
После подтверждения/конфликта/отмены — refetch карты и employee lookup,
после успешной отмены — списка. Поиск сотрудников также инвалидируется.
«Мои бронирования»: loading/error/retry/empty,
confirmed/cancelled, офис/этаж/тип/ID/МСК/код, без чужих бронирований.
Booking GET `/bookings/me` получает расположение одним joined query; все прежние поля
и JSON-сериализация времени сохранены. POST/cancel, авторизация, GiST, транзакция и
outbox не менялись. Миграций нет. SMTP и real Assistant остаются WB-07/WB-06.

## Риски и rollback
Профили/данные вымышлены, выбранный интервал — бронь, не физическое присутствие.
Откат — предыдущие immutable runtime images; schema не меняется, новые поля списка
additive. При неизвестном исходе подтверждения предлагается только повтор исходной
операции; проверить её можно также в собственных бронированиях. Закрытие вкладки
целиком удаляет sessionStorage; серверная идемпотентность и GiST остаются авторитетом.
Production пока v1.1.0. Задача не помечена завершённой/выпущенной.
