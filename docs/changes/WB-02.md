# WB-02 · Booking Core

## Пользовательское изменение
Booking API позволяет войти в вымышленный аккаунт, проверить доступность,
подтвердить бронь, посмотреть свои записи и отменить собственную бронь.
API доступен через Swagger; карта и форма приложения — отдельные WB-03/WB-05.

## Реальная реализация
- Ветка от merge WB-01 `e5bb0b5`; [issue #3](https://github.com/smalvik/biocad-workspace/issues/3).
- Локальный коммит реализации: `5f3f66174ab8ab9d1155a0331ea8abe880706690`.
- Alembic `0001_booking_core`: настоящая PostgreSQL-схема, GiST exclusion
  только для confirmed, `[start,end)`, CHECK интервала, per-user UNIQUE ключа.
- Подписанная HttpOnly cookie и серверная сессия в БД с TTL 8 часов;
  scrypt password hashes, CSRF для мутаций; logout отзывает сессию на сервере.
- Владельца определяет сервер; попытка передать employee_id/status в теле отклоняется.
- Нормализация aware ISO дат в UTC; fingerprint payload, replay после отмены,
  обработка параллельного повторного подтверждения.
- Бронь и versioned outbox-event в одной транзакции, включая исходный seed;
  cancel с блокировкой строки и единственным событием. Публикация событий — WB-07.
- Идемпотентный вымышленный seed без перезаписи данных и паролей;
  исправлены D-07/Анна, назначения, конфликтующая демобронь перенесена на D-08,
  роли Марии/Павла приведены к каноническому сценарию PRD.
- Ресурсы/доступность по интервалу, собственный список, коды ошибок и request ID.
  Этаж 3 пока без ресурсов; интерфейсные профили/поиск — WB-04.
- Booking Dockerfile собирается от корня репозитория для упаковки канонической
  фикстуры; `.dockerignore` исключает секреты, reference library и лишние файлы.
- [ADR-001](../adr/001-booking-consistency.md).

  Автоматический rollback схемы/production deploy не выполнялся.
